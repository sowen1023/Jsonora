# Jsonora 设计说明（内部参考）

简体中文 · [English](DESIGN-BRIEF.en.md)

> 一个 Chrome JSON 查看器扩展。产品使用与当前品牌信息以 [README](../README.md)、[品牌文档](BRAND.md) 和代码为准；本说明保留设计迭代时的问题与取舍。

---

## 1. 这是什么

Chrome 自带的 JSON 视图只有一行行原始文本；市面上的插件要么界面粗糙，要么在几十兆的文档上卡死，要么遇到不严格的 JSON（注释、尾随逗号、JSONP）就直接报错。

Jsonora 针对这三点重做：**界面是精心调过的**、**树视图是虚拟滚动的**、**解析器是容错的**。

典型使用场景按频率排序：

1. 打开一个 API 地址，左侧先显示带高亮的原始 JSON，右侧可在树形与图形结构之间切换
2. 从别处复制一段 JSON 粘进来，格式化、搜索、复制某个子节点
3. 在文档/博客里看到一段 JSON 代码块，就地展开来看
4. 在 DevTools 里调试接口响应

## 2. 运行环境与硬约束

这些约束会直接影响设计决策，请先读：

| 约束 | 说明 |
| --- | --- |
| **Chrome MV3 扩展** | 只能跑在 Chrome 里，不能是网页 |
| **必须注入到任意网站** | 查看器会以 Shadow DOM 形式覆盖在别人的页面上，宿主页面的 CSS 无法影响我们，但反过来也意味着**不能用任何依赖宿主环境的样式** |
| **弹窗尺寸** | 扩展弹窗最大约 800×600，实际按 348px 宽设计 |
| **字体** | 不能依赖用户装了某个字体。UI 用系统字体栈，代码用系统等宽字体栈。**目前没有打包任何字体文件**（打包会让扩展体积增加 ~40KB/字重，需要设计师决定值不值） |
| **深浅色** | 明暗两套都要设计，且要能跟随系统 |
| **内容不可信** | JSON 里的字符串可能是任何东西，包括超长无空格字符串、emoji、RTL 文字、中文 |

## 3. 界面清单

一共 10 个面。**1–4 是主体，占 90% 的使用时间**。

### 3.1 查看器（主界面）

既是独立标签页，也是覆盖在网页上的浮层 —— **同一套 UI，同一份 CSS**。

```
┌─────────────────────────────────────────────────────────────┐
│ ◈ Jsonora       文件  视图              搜索  中/EN  设置      │ 56px
├─────────────────────────────────────────────────────────────┤
│ JSON             [收起] │⋮│           紧凑 网格 [收起]        │ 38px
├─────────────────────────────────────────────────────────────┤
│  1  {                    │ │       $ ── user ── name          │
│  2    "user": {          │ │              └── tags           │
│  3      "name": "Ada"   │ │                                  │
│                          │ │                                  │
├─────────────────────────────────────────────────────────────┤
│ 1.8 KB · 14 节点 · 深度 1 · 对象 · 18 ms        $.user.name │ 30px
└─────────────────────────────────────────────────────────────┘
```

- **顶栏**：品牌标识 + 文件/视图菜单 + 搜索 + 中英文切换 + 设置；展开、折叠、格式化与排序位于设置面板
- **内容区**：左侧固定为原始 JSON，通过顶栏「视图」让右侧在图形与树形之间二选一；分隔线可拖动，两侧可独立收起
- **底栏**：统计信息（左）+ 当前选中节点的 JSONPath 和复制按钮（右）

当前截图：`docs/preview-current.png`（默认无网格）；旧设计截图保留在 `docs/preview-split*.png`

### 3.2 树形视图

一行一个 JSON 节点，24px 行高，虚拟滚动（只渲染视口内的行，40 万节点也流畅）。

一行 = 缩进参考线 + 展开箭头 + 键名 + `:` + 值。

- 键名蓝色，字符串绿色，数字橙色，布尔紫色，`null` 灰色斜体，括号青色
- 容器显示 `{…}` / `[…]` 及直接子项数
- 悬停整行变色，选中行左侧 2px 强调条
- 搜索命中用黄色 `<mark>` 高亮

**需要设计的地方**：行内信息层级目前只靠颜色区分，密度较高。是否有更好的方式表达「这是对象 / 数组 / 值」？

### 3.3 图形视图

节点图支持两种可即时切换的表达，父子之间用贝塞尔曲线连接，可平移缩放。

- **独立节点**：每个 JSON 节点是一个 30px 高圆角盒子，适合逐项追踪
- **紧凑卡片**：一个容器是一张卡片，直接字段成为卡片内的 29px 行；展开嵌套对象时，从对应字段行连接到下一张卡片
- 折叠状态由展开箭头和 `{…}` / `[…]` 表达，不再用容易产生歧义的虚线边框
- 边：细灰曲线，选中节点相连的边变强调色
- 网格默认关闭；可从图形面板标题栏或设置中开启。开启后使用 24px 淡点阵和 144px 稀疏主线
- 右下角悬浮控制条：缩放 −/+、百分比、适应窗口
- 重新布局时有 320ms 的位移动画，边同步补间

现有截图：`docs/preview-graph.png`、`docs/preview-compact.png`

### 3.4 原始视图

带语法高亮和行号的纯文本，同样是虚拟滚动的。

- 行号列 58px，右对齐，粘性定位（横向滚动时不跟着走）
- 支持自动换行开关
- 解析失败时出错行整行标红

### 3.5 空状态

用户第一次打开、或清空之后看到的界面。

- 42px 的 Jsonora J 字标（暖纸底、深色笔画与赤陶小方点）
- 标题「让复杂 JSON，清晰展开。」
- 细边框投放区，内含「粘贴 JSON」「选择文件」两个按钮
- 三个示例数据按钮
- 底部提示快捷键

### 3.6 错误状态

解析失败时。**这是这个产品最有价值的界面之一** —— 用户最需要帮助的时刻。

- 错误图标 + 标题
- **黄色提示条**：优先把 V8 的错误翻译成人话，例如「第 4 行末尾可能缺少逗号」
- 位置：第几行第几列 + 字符偏移；V8 原始错误降为次要信息
- 出错位置上下 2 行的代码片段，出错行高亮，下面有 `^` 指示符
- 三个操作按钮：在原始视图中查看 / 复制错误信息 / 换一个文件

现有截图：`docs/preview-error.png`

### 3.7 详情面板

点击任意节点的 `⋯` 后，从右侧打开检查面板。显示该节点的完整值（容器显示格式化 JSON）、JSONPath、类型、字节数、子项数，以及复制路径 / 复制值 / 下载三个操作。

现有截图：`docs/preview-detail.png`

### 3.8 扩展弹窗

348px 宽。三段卡片：

1. **当前页面**：检测状态 + 「在页面上渲染」按钮
2. **快速粘贴**：文本框 + 「格式化并打开」
3. **快捷键提示**

### 3.9 设置页

查看器内使用 410px 右侧设置面板，设置按钮在普通网页演示环境里也可直接使用；扩展另保留独立设置页。内置面板分组：语言 / 外观 / 查看器。

控件类型：主题预览卡片、分段控件（缩进）、开关、数字输入、下拉、滑块（字号）。

### 3.10 页内嵌入式查看器 + 右下角胶囊

在普通网页里检测到 JSON 代码块时：

- 右下角出现胶囊按钮「渲染 N 段 JSON」，可关闭
- 点击后把每个 `<pre>` 就地替换成 520px 高的嵌入式查看器

## 4. 现有设计系统

全部定义在 `src/ui/styles/tokens.css`，改一处全局生效。

### 4.1 主题方案

参考 qevi-studio **docs 文档页面的整体界面语言**，而不是 qevi-studio Studio/BFF 的配色。明暗模式与色板是两个独立维度：明暗提供浅色、深色、跟随系统；每套色板都同时包含完整的浅色和深色。

| 色板 | 浅色背景 / 强调 | 深色背景 / 强调 | 定位 |
| --- | --- | --- | --- |
| VS Code（默认） | `#ffffff` / `#005fb8` | `#1f1f1f` / `#75bfff` | Modern 工作台层次与 JSON 语法色 |
| GitHub Classic | `#ffffff` / `#0969da` | `#0d1117` / `#58a6ff` | GitHub 经典浅色与深色 |
| GitHub Dimmed | `#f6f8fa` / `#0969da` | `#22272e` / `#539bf5` | 较柔和的明暗层级 |
| GitHub Contrast | `#ffffff` / `#0349b4` | `#0a0c10` / `#71b7ff` | 更高对比度 |

当前实机截图：`docs/preview-raw.png`、`docs/preview-settings.png`、`docs/preview-menu.png`、`docs/preview-graph.png`。

### 4.2 JSON 语法配色（默认 VS Code 深色）

| 语义 | 变量 | 值 |
| --- | --- | --- |
| 键名 | `--t-key` | `#9cdcfe` |
| 字符串 | `--t-string` | `#ce9178` |
| 数字 | `--t-number` | `#b5cea8` |
| 布尔 | `--t-bool` | `#569cd6` |
| null | `--t-null` | `#c586c0` |
| 成对括号 | `--t-brace-0/1/2` | `#ffd700` / `#da70d6` / `#179fff` |
| 标点 | `--t-punct` | `#cccccc` |
| 缩进引导线 | `--raw-guide` | `#404040` |

### 4.3 配色原则

- 大面积区域保持中性；色板强调色只出现在选中、焦点、页头细线和 JSON 类型色。
- 顶栏只使用单色细线，不使用光谱渐变或高亮光晕。
- JSON 面板保持纯净底色；只有图形画布支持可选网格，且默认关闭。
- 菜单、详情面板和 HUD 使用实色层级与轻阴影，不用高亮光晕。

### 4.4 形状与动效

| 变量 | 值 |
| --- | --- |
| 圆角 | 3 / 5 / 7 / 9px（xs / sm / 默认 / lg） |
| 阴影 | `0 1px 2px rgba(0,0,0,.28)` / `0 14px 36px rgba(0,0,0,.38)` / `0 28px 72px rgba(0,0,0,.50)` |
| 缓动（常规） | `cubic-bezier(.22, 1, .36, 1)` |
| 缓动（弹性） | `cubic-bezier(.34, 1.4, .64, 1)` |
| 时长 | 120ms / 180ms / 220ms |
| 树行高 | 24px |
| 缩进步长 | 16px |
| 原始视图行高 | 20px |
| 字号 | 13px（可在设置里 11–18 调） |

### 4.5 字体

```
UI:   Inter, "Avenir Next", "SF Pro Text", -apple-system, BlinkMacSystemFont,
      "Segoe UI Variable Text", "Segoe UI", "PingFang SC", "Microsoft YaHei UI", system-ui, sans-serif

标题: Georgia, "Iowan Old Style", "Noto Serif CJK SC", "Source Han Serif SC",
      "Songti SC", SimSun, serif

代码（默认）: "Jsonora JetBrains Mono", Menlo, Consolas,
      "PingFang SC", "Microsoft YaHei", monospace
```

标题使用文档式衬线栈，控件与正文使用清晰的无衬线栈。JSON 内容可选内置的 JetBrains Mono、Fira Code、Inconsolata，或本机安装的 Menlo、Monaco、Courier New；中文内容回退到 PingFang SC / 微软雅黑。

### 4.6 动效清单

已实现的动效（都可以在设置里整体关掉）：

- 展开/折叠时，新出现的行错峰淡入（每行延迟 13ms，最多 24 行）
- 展开箭头 180ms 弹性旋转
- 视图切换标签的滑动指示器
- 图形视图重新布局：节点 320ms 位移 + 边同步贝塞尔补间
- 主题切换的颜色过渡
- Toast 从底部弹入
- 详情检查面板从右侧平稳进入
- 顶栏从上方滑入
- 尊重系统的「减少动态效果」

## 6. 需要设计介入的问题（按优先级）

### P0 — 图形视图的方向（已提供双模式）

**A 版**：一行一个节点，圆角小盒子，父子用曲线连接。适合先看清整体结构。

**B 版（默认）**：紧凑多行卡片把对象的直接字段收进一个区域，只有展开的容器才生成下一张卡片。适合读懂某个对象或子树。

两种模式共享展开状态、搜索命中、选中节点、缩放和平移，用户可以在图形面板标题栏即时切换。大文档超过预算时仍会自动折叠分支。

### P1 — 代码字体

目前提供六种可持久化选择：内置 JetBrains Mono（默认）、Fira Code、Inconsolata，以及依赖本机安装的 Menlo、Monaco、Courier New。只打包内置字体的 Latin WOFF2 子集；中文继续回退到 PingFang SC / 微软雅黑，不额外打包大体积中文字体。

另外需要定：JSON 正文的字号、字重、行高。现在默认是 13px / 400 / 行高 24px（树）、22px（原始视图）。

### P2 — 信息密度

树视图一行里有：缩进参考线、箭头、键名、冒号、值、逗号、可选徽章（超长字符串长度、大整数精度警告）、悬停时出现的 `⋯` 按钮。

需要设计师判断：默认密度是否过高？哪些信息可以延后到详情面板？徽章应该长什么样？

### P3 — 空状态与首次体验

现在的空状态比较朴素。这是用户对产品的第一印象，值得单独设计。

### P4 — 图标系统

现在所有图标都是手写的 24×24 描边图标（`src/ui/Icons.tsx`），描边 2px，圆头圆角。没有统一的图标库，风格是我自己调的。

需要设计师确认：是否统一替换成一套现成图标库（如 Lucide / Phosphor），还是保持手写？

### P5 — 品牌

标识已更新为暖纸色圆角方块与深色 J 字形、赤陶色小方点。矢量稿、PNG 用途与用色见 [品牌文档](BRAND.md)。

## 7. 交付建议

如果需要，可以按这个顺序出稿：

1. **图形视图**（P0）—— 这是唯一会改变信息架构的界面，先定它
2. **字体与排版规范**（P1）—— 定完全局生效，成本低收益高
3. **树视图的密度与徽章**（P2）
4. **空状态 + 首次体验**（P3）
5. 图标系统 + 品牌（P4/P5）

交付格式：Figma 优先。**请直接使用第 4 节的变量名作为 Figma 变量名**，这样设计和代码能一一对应。
